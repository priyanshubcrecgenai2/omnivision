Edge Vehicle Telemetry & Spatial Rule Enforcement

A fixed camera stream processes through YOLOv11 and ByteTrack. The system checks vehicle tire contact points against custom 4-point perspective polygons, records directional flow, and queues structured event records into an SQLite database with Write-Ahead Logging.

Python 3.10+ YOLOv11 CUDA FP16 ByteTrack OpenCV SQLite WAL Flask / MJPEG Chart.js
View repository & code on GitHub ↗
Operations Analytics Center

Pipeline Architecture & Implementation

  • CUDA FP16 execution: YOLOv11 runs on NVIDIA Tensor Cores at 25 to 35 frames per second on 720p and 1080p feeds.
  • Ground-contact polygon testing: Elevated cameras distort bounding box centroids relative to actual road lanes. The geometry module evaluates the bottom-center tire contact coordinates (cx, y2) with cv2.pointPolygonTest to assign vehicles to lanes accurately.
  • Streak verification filter: Directional mismatch and zone intrusion alerts require 4 consecutive confirmed frames before recording an event. This rejects false triggers caused by detector bounding box jitter.
  • Decoupled database worker: Disk operations run in a background daemon thread with SQLite Write-Ahead Logging (WAL) and batch commits. Write overhead inside the primary computer vision loop remains under 0.3 ms.
  • First-frame canvas configurator: Web-based interface where operators click 4 coordinate points to define perspective lane boundaries without editing configuration files.
